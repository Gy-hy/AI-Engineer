# AI System Engineer Curriculum

AI 系统工程师完整培养计划 — 从 Python 基础到生产级 AI 基础设施的工程化学习路线。

## 项目定位

这是一个长期维护的课程型仓库，不只是学习目标清单。

仓库将逐步同时承载：

- 学习目标
- 教程正文
- 学习笔记
- 习题
- 参考答案
- 示例代码
- 阶段项目与综合项目

面向对象包括：

- 仓库维护者
- 多人协作者
- 外部读者
- 按路线系统学习的工程师

## 五层架构

```
Layer 1: Software Engineering → Python · Git · Linux · Docker · Network
Layer 2: Backend Engineering   → FastAPI · Database · MQ · Object Storage · Search
Layer 3: AI Engineering        → LLM · RAG · Agent · MCP · AI Product · Evaluation
Layer 4: AI Infrastructure     → GPU · Inference · K8s · Monitoring · CI/CD · Cloud
Layer 5: Architecture & Career → System Design · Open Source · Source Reading · English
```

每一层都包含**学习要点**、**必做项目**和**综合毕业项目**，完成后进入下一层。

## 快速开始

```bash
git clone https://github.com/Gy-hy/AI-Engineer.git
cd AI-Engineer

# 创建虚拟环境（需要 Python 3.12）
uv venv ai-engineer --python 3.12
source ai-engineer/bin/activate
uv pip install -r requirements.txt
mkdocs serve
```

## 文档站

仓库计划使用 `MkDocs + Material for MkDocs` 作为对外展示层。

它承担的职责是：

- 提供课程网站与公开阅读入口
- 提供按学习路径组织的导航
- 提供搜索、目录、代码块展示、索引页等文档能力

它**不等于**仓库底层内容结构本身。

本仓库采用的原则是：

- 源文件按“主题单元”组织，方便多人协作维护
- 网站按“学习路径”组织，方便读者浏览

也就是：

- **维护视角**和**阅读视角**分离

## 已确定的信息架构方案

项目采用 **方案 C：双层结构式（主题单元 + 读者入口）**。

核心原则：

1. 底层内容按主题单元维护
2. 顶层文档按课程路径聚合展示
3. 小示例代码跟主题走
4. 大项目集中管理
5. 答案与教程同仓库维护，但默认弱曝光
6. 文件名尽量使用中文，并保留编号

## 主题单元标准模板

课程内容的最小维护单位是“主题单元”。

推荐结构如下：

```text
内容/主题/第3层 AI工程/3.2 RAG/
  01 学习目标.md
  02 教程.md
  03 习题.md
  04 答案.md
  资源/
  示例代码/
```

各部分职责如下：

- `01 学习目标.md`
  - 目标、必学内容、必做项目、毕业标准
- `02 教程.md`
  - 面向读者连续阅读的正式教程正文
- `03 习题.md`
  - 选择题、思考题、动手题、延伸题
- `04 答案.md`
  - 参考答案、讲解、参考实现
- `资源/`
  - 当前主题专属图片、图表、附件
- `示例代码/`
  - 当前主题的小示例、小实验、小片段

说明：

- `01 学习目标.md` 与 `02 教程.md` 是核心文件
- `03 习题.md`、`04 答案.md`、`资源/`、`示例代码/` 可按内容成熟度逐步补充

## 命名规范

命名尽量使用中文，同时保留编号。

规范如下：

- 顶层与内容目录使用中文
  - 例如：`内容/`、`指南/`、`主题/`、`项目/`、`共享/`
- 主题目录保留编号
  - 例如：`1.1 Python高级`、`3.2 RAG`、`4.5 CI_CD`
- 主题内部文档使用固定中文文件名
  - `01 学习目标.md`
  - `02 教程.md`
  - `03 习题.md`
  - `04 答案.md`
- 主题内部资源目录使用固定中文名称
  - `资源/`
  - `示例代码/`

这样做的目的：

- 与当前仓库已有命名风格保持一致
- 对中文协作者更直观
- 保证排序、导航、搜索稳定

## 代码组织规范

项目采用混合代码组织方式：

- 小示例代码跟主题走
- 大项目集中在 `项目/`

推荐规则：

- 如果代码只服务于单个知识点或单个主题，放在该主题的 `示例代码/`
- 如果代码跨多个主题复用，或本身已是完整工程，放在 `项目/`

例如：

- `内容/主题/第3层 AI工程/3.2 RAG/示例代码/`
- `项目/企业知识库/`
- `项目/Agent平台/`

## 答案管理规范

习题答案与教程放在同一仓库维护，但默认弱曝光。

当前约定如下：

- `04 答案.md` 保留在主题目录中
- 站点主导航默认不高曝光答案页
- `03 习题.md` 可以链接到 `04 答案.md`
- 如后续有需要，可再扩展为公开版与内部版两套导航

这意味着：

- 仓库维护成本较低
- 协作者容易同步修改
- 普通读者不会在主导航中直接看到所有答案

## 协作原则

为保证多人协作可持续，后续内容维护遵循以下原则：

1. 以“主题单元”为最小维护单位，而不是按文档类型拆散维护
2. 优先保证结构统一，再逐步补充内容
3. 优先补齐 `01 学习目标.md` 与 `02 教程.md`
4. 习题、答案、示例代码按主题成熟度逐步增加
5. 大项目单独管理，不与单主题小示例混放
6. 对外展示通过 MkDocs 导航控制，不要求磁盘结构直接等于网站结构

## 学习方式

1. 从 `AI_System_Engineer_Curriculum.md` 开始，建立全局认知
2. 按层级顺序推进，不要跳层
3. 每个模块的「必做项目」必须动手完成
4. 每个阶段结束完成「综合毕业项目」再进入下一层
