# Curriculum Repo Structure Design

## 背景

当前仓库最初用于维护 `Learning objectives/` 下的学习目标文档，内容以课程大纲和各主题目标为主。

后续仓库将逐步扩展为一个完整的课程型仓库，除了学习目标外，还将承载：

- 教程正文
- 学习笔记
- 习题
- 参考答案
- 小型示例代码
- 阶段项目与综合项目

该仓库还需要满足以下约束：

- 使用 `MkDocs + Material for MkDocs` 作为对外展示层
- 面向多人协作维护
- 需要给外部读者阅读
- 文件名尽量使用中文
- 习题答案与教程同仓库维护，但默认弱曝光
- 小示例代码跟主题走，大项目集中管理

## 已确认决策

### 1. 整体组织方案

采用 **方案 C：双层结构式（主题单元 + 读者入口）**。

这意味着：

- 源文件按“主题单元”组织，便于多人协作维护
- 文档站按“学习路径”组织，便于外部读者浏览
- 仓库底层结构不要求与网站导航一一对应

### 2. 答案管理策略

习题答案与公开教程放在同一仓库中维护，但默认弱曝光：

- 保留 `04 答案.md`
- 站点主导航默认不高曝光答案页
- `03 习题.md` 可链接到 `04 答案.md`
- 后续如有需要，可扩展为公开版 / 内部版两套导航

### 3. 代码组织策略

采用混合模式：

- 小示例代码跟主题单元走
- 大项目统一放入 `项目/`

### 4. 命名策略

文件名与目录名尽量使用中文，同时保留主题编号，便于：

- 排序
- 搜索
- 导航稳定
- 与现有命名风格保持一致

## 目标结构

未来仓库的目标结构如下：

```text
.
├── CLAUDE.md
├── README.md
├── requirements.txt
├── mkdocs.yml
├── 内容/
│   ├── 指南/
│   └── 主题/
├── 项目/
├── 共享/
└── main.py
```

### 各目录职责

#### `内容/指南/`

用于承载面向读者的聚合页与入口页，例如：

- 课程总览
- 学习路径
- 习题索引
- 项目索引
- FAQ
- 贡献指南

#### `内容/主题/`

用于承载课程主体内容，按 Layer 和主题单元组织。

这是内容维护的核心区域。

#### `项目/`

用于承载跨多个主题的大项目、阶段项目、综合项目。

#### `共享/`

用于承载可被多个主题复用的公共资源，例如：

- 通用图片
- 模板
- 复用片段

## 主题单元模板

主题单元是后续仓库的最小维护单位。

示例：

```text
内容/主题/第3层 AI工程/3.2 RAG/
  01 学习目标.md
  02 教程.md
  03 习题.md
  04 答案.md
  资源/
  示例代码/
```

### 文件职责

#### `01 学习目标.md`

用于维护：

- 学习目标
- 必学内容
- 必做项目
- 毕业标准

#### `02 教程.md`

用于维护正式教程正文，面向读者连续阅读。

#### `03 习题.md`

用于维护：

- 选择题
- 思考题
- 动手题
- 延伸题

#### `04 答案.md`

用于维护：

- 参考答案
- 讲解
- 参考实现说明

#### `资源/`

用于存放当前主题专属图片、图表、附件。

#### `示例代码/`

用于存放当前主题的小示例、小实验、小片段。

### 必选与可选项

每个主题默认至少具备：

- `01 学习目标.md`
- `02 教程.md`

其余部分可按内容成熟度逐步增加：

- `03 习题.md`
- `04 答案.md`
- `资源/`
- `示例代码/`

## 命名规范

### 顶层目录

使用中文：

- `内容/`
- `指南/`
- `主题/`
- `项目/`
- `共享/`

### 主题目录

保留编号：

- `1.1 Python高级`
- `3.2 RAG`
- `4.5 CI_CD`

### 主题内部文件

固定为中文并带序号：

- `01 学习目标.md`
- `02 教程.md`
- `03 习题.md`
- `04 答案.md`

### 主题内部资源目录

固定为中文：

- `资源/`
- `示例代码/`

## MkDocs 使用边界

`MkDocs + Material for MkDocs` 作为展示层使用，不直接决定仓库底层结构。

它的职责是：

- 组织导航
- 提供搜索
- 提供对外课程阅读体验

仓库底层结构则优先服务于：

- 多人协作
- 主题单元维护
- 代码与内容长期扩展

## 迁移策略

当前 `Learning objectives/` 属于过渡阶段内容。

迁移策略采用渐进式：

1. 先确定目标结构与命名规范
2. 先创建目录骨架与最小占位文件
3. 选择 1 到 2 个主题作为样板迁移
4. 验证 MkDocs 导航映射效果
5. 再逐步迁移其余主题

## 本阶段范围

本阶段只做以下事情：

1. 确认方案 C
2. 将规范写入 `README.md`
3. 生成目录骨架与最小占位文件
4. 为后续 `mkdocs.yml` 与内容迁移做准备

本阶段不做：

- 全量迁移旧内容
- 完整撰写所有教程
- 一次性生成所有项目代码

## 推荐后续步骤

1. 生成实际目录骨架与最小占位文件
2. 创建 `mkdocs.yml`
3. 先接入 `内容/指南/` 与 1 到 2 个主题样板
4. 再逐步迁移 `Learning objectives/` 内容
