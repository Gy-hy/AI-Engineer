# 5.1 Architecture（★★★★★）

> **目标：建立面向复杂 AI 系统的架构判断力，能够设计可扩展、可维护、可演进的生产级系统，而不仅是把功能堆在一起。**

---

# 1. SOLID（★★★★★）

## 必学内容

掌握：

* 单一职责
* 开闭原则
* 里氏替换
* 接口隔离
* 依赖倒置

理解：

为什么工程规模一大，代码质量问题最终都会变成架构问题。

---

## 必做项目

选取：

一个你写过的 AI 服务模块。

重构：

使其更符合 SOLID。

---

# 2. Clean Architecture（★★★★★）

## 必学内容

理解：

* Domain
* Use Case
* Interface Adapter
* Infrastructure

理解：

为什么业务逻辑不能直接绑死在框架和数据库上。

---

## 必做项目

将：

一个 FastAPI + LLM / RAG 服务

重构为：

清晰的分层架构。

---

# 3. DDD（★★★★☆）

## 必学内容

理解：

* Entity
* Value Object
* Aggregate
* Repository
* Bounded Context

理解：

什么时候系统复杂度已经高到需要 DDD 思维，而不是简单 CRUD。

---

## 必做项目

为：

AI Workspace / Knowledge Base / Agent Task System

划分：

核心领域模型。

---

# 4. Hexagonal Architecture（★★★★☆）

## 必学内容

理解：

* Port
* Adapter
* Driving Adapter
* Driven Adapter

理解：

为什么 AI 系统特别适合通过 Port/Adapter 隔离外部依赖。

---

## 必做项目

为：

LLM Provider、Vector DB、MCP、Object Storage

设计：

统一适配层。

---

# 5. Monolith vs Microservice（★★★★★）

## 必学内容

掌握：

* Monolith
* Modular Monolith
* Microservice
* Service Boundary

理解：

为什么很多团队不是“不会微服务”，而是“过早微服务”。

---

## 必做项目

为一个 AI 平台设计：

* 单体版架构
* 微服务版架构

并写出取舍分析。

---

# 6. Event Driven（★★★★★）

## 必学内容

掌握：

* Event
* Publisher
* Consumer
* Async Workflow
* Event Bus

理解：

为什么文档解析、索引构建、Agent 异步执行都适合事件驱动。

---

## 必做项目

将：

文档上传 → 解析 → Chunk → Embedding → Index

改造成：

事件驱动流程。

---

架构成本拆解表。

# Architecture 综合毕业项目（★★★★★）

> **AI System Architecture Design**

## 功能要求

* 提供完整系统架构图
* 定义模块边界与职责
* 说明单体 / 微服务取舍
* 说明缓存、扩展、安全、限流方案
* 说明事件驱动链路
* 说明高可用与成本控制策略

---

## 毕业标准（★★★★★）

完成该项目后，你应达到以下能力：

* 能从“功能实现者”升级为“系统设计者”。
* 能为复杂 AI 系统定义清晰边界，而不是让所有模块相互耦合。
* 能在扩展性、安全性、稳定性、成本之间做工程化取舍。
