    db_session¶

    对应章节¶

    • 主题：1.1 Python高级
    • 对应教程章节：05 Context Manager
    • 关联内容：
    • 上下文管理器协议（__enter__ / __exit__）
    • contextlib.contextmanager（生成器写法）
    • 事务边界与连接生命周期管理

    项目目标¶

    实现一个数据库会话管理器，满足三条硬要求：

    1. 自动提交：with 块正常结束 → 自动 commit。
    2. 自动回滚：with 块抛异常 → 自动 rollback，且异常继续向上传播（不吞）。
    3. 自动关闭：无论提交还是回滚 → 连接自动 close。

    用标准库 sqlite3 演示（零依赖、可复现），同样的模式适用于任何提供 commit/rollback/close 的驱动（psycopg、pymysql 等）。

    为什么不用 sqlite3 自带的 with conn？ 它只管理事务（commit/rollback），不管理连接生命周期（close）。本项目的 DatabaseSession 是它的增强版：在事务管理之上，额外负责连接的开与关。

    已实现¶

    实现 方式 特点
    DatabaseSession 类（__enter__/__exit__） 显式、可存状态、可复用
    database_session @contextmanager 生成器 简洁、一次性的场景首选

    两个实现功能等价，用于对比两种写法的取舍。

    目录结构¶

    db_session/
├── session_manager.py   # 两种实现（类版本 + @contextmanager 版本）
├── demo.py              # 演示脚本：验证三条要求
└── README.md

    快速开始¶

    cd "内容/主题/第1层 软件工程/1.1 Python高级/示例代码/db_session"
python3 demo.py

    期望输出（关键点）：

    1. 自动提交：with 块正常结束 -> commit 生效
   提交后查询到： [('alice',)]
2. 自动回滚：with 块抛异常 -> rollback，异常向上传播
   捕获到传播的异常： 模拟业务出错
   回滚后查询到： [('alice',)]          ← bob 未被写入
3. 自动关闭：with 块结束后连接已 close
   连接已关闭，报错符合预期： Cannot operate on a closed database.
4. @contextmanager 版本同样满足三条要求
   提交后查询到： [('alice',), ('carol',)]
